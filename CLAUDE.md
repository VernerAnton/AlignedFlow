# AlignedFlow

A Vite + React PWA: a workday posture timer (work mode) and an evening stretch
routine (evening mode), each with its own builder for editing presets.

## Bump the version when work ships

`src/version.js` holds a single hand-maintained integer, `APP_VERSION`.
**Increment it by one in any change that ships**, in the same commit as the
work itself.

It exists because the app is installed on several devices, and a service
worker can go on serving an old build long after a new one has deployed.
The number is what makes "am I on the current build?" answerable at a glance
by comparing two screens — it is a count of builds shipped since the counter
was added, not a semver release, so it does not track `package.json`.

It is deliberately manual rather than derived from the commit count: a version
should mark a change worth noticing, and the bump should be a one-line diff
that is obvious in review. Nothing enforces it, which is why it is written
down here.

`__BUILD_COMMIT__` and `__BUILD_TIME__` are injected by `vite.config.js` and
need no attention.

## Service worker

The worker is generated by `vite-plugin-pwa` under `registerType: 'autoUpdate'`,
but registered by the app itself in `src/useAppUpdate.js`, with
`injectRegister: null` in the plugin config so it is not registered twice.

That is deliberate. The plugin's own client reloads the page the moment a new
worker activates, with no callback to intervene in 0.21.x — check
`node_modules/vite-plugin-pwa/dist/client/build/register.js` before assuming
otherwise. Registering directly against `navigator.serviceWorker` lets a new
build announce itself through `UpdatePrompt` instead. **Never reload
automatically**: a reload nobody asked for discards a running timer and
anything half-typed into a builder.

## Conventions

- Inline `style` objects, no CSS files. `'DM Mono', monospace` throughout.
- Dark palette: `#0f0e0c` background, `#f0ece4` text, hairline
  `rgba(255,255,255,0.x)` borders.
- Flat `src/`, one component per file, default exports for components.
- Comments explain why a thing is the way it is, not what the line does.
